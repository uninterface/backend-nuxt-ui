# Selection, feedback and panels

## Multiple selection

UiMultiSelect uses USelect multiple, joined to a compact native UButton clear icon through UFieldGroup. USelect has no built-in clear prop; the sibling button avoids nesting a button inside its trigger. It edits the complete field-owned string array; codecs translate business values. Clearing preserves loaded disabled selections and is available only when editable memberships exist in a ready source. Missing selected choices remain visible and removable after a ready response. Pending/error sources retain current values and block candidate edits. This is separate from UiSelect's single-value surface.

The popup keeps its choices inside the owning modal's interaction scope. Selected values, available choices and source feedback are independent. See the core multiple-selection guide for source lifetime and validation.

## Inline feedback and record details

UiNotice and UiBadge use UAlert and UBadge. Severity never forces announcement: core supplies explicit off/polite/assertive policy. Badges are passive textual labels, not action chips or live counters.

UiKeyValueList/Item render dl/dt/dd with a two-column desktop arrangement and stacked labels/values below 40rem. Rich values remain opaque; business code supplies Intl formatting, empty/redacted wording and access policy. Exact spacing, typography and native theme colors are adapter presentation. Ordinary content needs no consumer stylesheet. Application-owned configuration and styles from the existing customization guide also cover these surfaces; there are no new business presentation knobs.

## Tabs and collapsibles

The bar uses UTabs with content=false and activationMode=manual, preserving Nuxt native theme slots and indicator. UiTabPanel owns separately placed content. UTabs does not expose arbitrary trigger attributes or external panel IDs, so the adapter synchronizes these after mount/update. Initial server HTML therefore does not have the final external-panel associations; hydration is required. Native selection follows mousedown; the backend DOM test adapter models that pointer path, while shared tests remain toolkit-independent. Manual activation uses arrows/Home/End for focus and Enter/Space or pointer activation for selection. UiTab default slots supply labels, including passive icons/badges. UiTabsBinding and separately placed UiTabPanelBindings share one selection; no panel containment in the tab bar is required. Stable values preserve panels and disabled triggers are skipped. Full-height panels fill a definite business-owned allocation; their inner layout owns scrolling.


UiCollapsible uses Reka Accordion primitives with the generated Nuxt accordion theme, configured chevronDown icon, native trigger/label/body slots and motion. It is a labeled panel presentation; UCollapsible itself is an unstyled-trigger composition. AccordionHeader renders as div, so no heading rank is imposed. Native roots receive explicit controlled values, and unmountOnHide=false preserves content. Core still controls lazy first mounting; closed content is inert. Supported as-child composition supplies the core trigger/content IDs and their associations from the initial render: the installed Reka context otherwise leaves a newly mounted closed trigger's aria-controls empty until another update. No private context mutation is used. Rich summary children use native inline-flex/wrapping/gap utilities. Application ui.accordion theme overrides and configured icons are consumed through the existing backend Vite configuration. Each view owns a one-item native root. Reka’s supported `as-child` composition places that root and item on the same DOM element, so directly adjacent UiCollapsible instances participate in Nuxt’s native border rules: boundaries between items, with the final boundary omitted. No theme classes are removed or replaced. Root and item theme slots apply to that shared element. This is local presentation, not a shared accordion state or keyboard-navigation group. Use direct siblings for an adjacent sequence; UiLayout remains appropriate for separate spatial allocations and retains its normal peer gap. Arbitrary wrappers are not traversed or regrouped. Application `ui.accordion` overrides continue to use native merging, including `slots.item: 'border-b-0'` to remove boundaries or `slots.item: 'last:border-b-2'` to request a final boundary.

Nuxt’s default accordion trigger uses `font-medium` (500). The documentation website uses Public Sans; this backend now supplies Public Sans Variable through its normal stylesheet, including weight 500. See [typography](typography.md) for font loading, language fallbacks and application overrides. The accordion retains its native medium weight rather than a bold (700) substitute.

UiCollapsible accepts a plain label or noninteractive summary slot. The backend supplies the operable toggle; summary content must include meaningful accessible text and cannot contain nested buttons, links or inputs. Core resolves standalone v-model or UiCollapsibleBinding, including local disabled restrictions. No backend imports the expansion control. That control supports at-most-one or multiple expanded keys, preserving state across view unmount/remount.

UiTabPanel and UiCollapsible retain mounted content. Lazy defers only first mount. Collapsing does not stop validation or background work. Reveal content before focusing a field. Native motion, markup and theme treatment vary; application-level theme customization follows this backend's existing customization guide. Controls do not require business-side CSS.

## Collapsible color

Does not declare `collapsible.color.v1`. Core ignores the optional color request and preserves the installed v4 Accordion treatment. Existing application ui.accordion theme customization remains available. Nuxt UI v2 documentation describes a different button-based API with color/variant props; that is not the installed implementation.

## Verification and limits

Shared DOM integration covers selection codecs/retention/clear/source states, notice urgency, passive badge semantics, definition-list associations, manual tab movement, lazy retained content and collapsible ownership. Those tests do not establish browser geometry, actual inert focus exclusion, visual focus quality, assistive-technology announcements or touch behavior. Preserve native palette policy, including the separately documented contrast limits of toolkit defaults. See the core component references and feedback/panels guides for consumer obligations.

Native composition checks are backend-owned; shared tests verify ownership, denied requests, summary naming, local disabled coordination, lazy retention and disposal. Native-reference fixtures provide side-by-side collapsible comparisons for toolkit backends. These checks distinguish rendered/source evidence from actual browser appearance; browser comparison remains required.

The backend-owned collapsible comparison fixture checks three matching native/adapter panels. DOM checks cover theme classes, direct adjacency, expansion, reordering/removal, retained drafts and application overrides. Browser checks compare computed trigger/label typography, borders, panel geometry and spacing in desktop/mobile, light/dark and LTR/RTL states; these must execute successfully before claiming visual acceptance.

## Scrolling content and focus clearance

UiContent supports content/full height and named scrolling, with insets inside the scroll boundary. Use it when a content inset is intended. Use scrolling UiLayout/UiGridLayout for flush content; unpadded scrolling scopes adapt supported outward focus outlines inward without changing alignment. Padded content/card/modal surfaces reset that placement context. The backend keeps scroll-host and tab-panel focus indicators inward. Modal bodies own their own internal clearance and preserve native browser focus scrolling. Do not add another content inset solely to repair focus. Allocation-only layouts still add no content gutter. Native control focus offsets adapt inside unpadded scroll hosts. Custom or third-party focus treatments need their own integration checks. See the core package’s `docs/guides/scrolling-content.md` guide. Browser clearance checks cover the public focus binding; native paint/custom-theme acceptance still requires browser verification.

## Notice dismissal and presentation

UiNotice uses UAlert with its native description/actions slots and close button. Core's localized close label is passed to the native button. Native update:open requests dismissal without hiding the component. Native wrapping action layout is preserved, and unbroken message references can wrap within the content column.

Dismissal is opt-in through dismissible. The close control requests dismissal; business code decides visibility and focus handoff. Recovery actions retain source and tab order with backend-owned spacing and wrapping below the message. No automatic dismissal, timer or Escape handling is installed. Rich custom actions own their internal layout. Shared DOM checks cover denied/repeated/accepted dismissal, live language changes, content retention and announcement semantics; browser checks cover keyboard activation, demo focus return and narrow LTR/RTL geometry. DOM success does not establish visual or assistive-technology acceptance.

## Notice presentation

Default explicitly selects native subtle; filled/outline/soft map to solid/outline/soft. Custom colors use the configured native palette (danger → error), and omission selects neutral. The native leading slot receives local semantic artwork or the authoritative custom icon slot, using the generated native icon class. No remote icon lookup is introduced. Ordinary links on filled notices inherit foreground.

UiNotice now supports custom kind/color and filled/outline/soft variants. The core rejects color on standard kinds and rejects undeclared or unsupported theme roles. A supplied icon slot always wins, even if empty; otherwise standard kinds supply their icon and custom supplies none. Icons are decorative/noninteractive; message text carries meaning. Declaration requires notice.color.v1, notice.variant.v1 and notice.icon.v1 alongside notice.v1. Applications customize through the existing backend theme setup; no business-side CSS is required. Native theme defaults remain in force unless a notice requests a treatment.

Focused five-backend DOM checks cover slot replacement, empty-slot suppression, neutral/custom colors, rejected combinations, retained content/focus and controlled dismissal. Browser cases cover variant/color/mode combinations, narrow geometry, icons and keyboard dismissal. Execution/visual acceptance must be recorded separately; passing DOM checks does not establish paint, contrast or assistive-technology conformance. See the shared feedback guide in `@uninterface/uninterface` (`docs/guides/feedback-and-details.md`).


### Notice action alignment

When the action row starts with a directly rendered text UiButton, its leading content aligns with the message column by hanging the native button inset into the notice's leading space. The row moves as a unit: button padding, height, hit targets, hover/focus treatment and gaps remain native. Logical margins support RTL; filled/outline/soft/icon-led rows retain ordinary boundary alignment. A leading icon or loading indicator is the aligned content; subsequent labels keep native icon/indicator spacing. Rich compositions own their internal alignment. Wrapped rows share the same origin; differently sized controls retain their own padding.

Without a notice icon, hanging is limited to the available inset so targets and focus remain inside the frame; exact label alignment can yield to containment. Applications that customize button padding can set `--nuxt-notice-action-inset` on `.nuxt-notice-actions` to the leading button's padding plus border inset. Native size mappings supply the ordinary value; this is backend-owned integration, not a business prop. If changing notice insets too, review target/focus containment and the backend's private maximum-hang rule.

Check wide/narrow LTR and RTL, native size levels, a single action, multiple/wrapped actions, explicit variants, loading and keyboard focus. DOM checks verify selectors match live button hosts; browser geometry and visual acceptance remain separate.

## Toast and notification targets

Supports core createUiToastTarget/createUiNotificationTarget and feedback.floating.v1. Targets render automatically in their creation scope, with configurable admission/capacity/duration and per-delivery Vue content. Queue options belong to target creation, not toolkit-global service configuration. Core owns the sole duration clock and summary announcement policy. See the core guide at docs/guides/toasts-and-notifications.md.

Toasts use isolated controlled UToast/Reka provider and viewport instances, without shared useToast state or cached Toaster height offsets. Native Presence owns exit, Toaster theme classes supply entry/exit motion, and native timers are disabled. Native announcement extraction excludes rich content; a separate summary live region supplies the selected policy. Swipe is disabled to preserve content scrolling. Guarded integration suppresses Reka’s document-wide Escape handler only on managed toasts; focused-item Escape belongs to the shared interaction protocol.

As an Uninterface backend default, dark-mode toasts select Nuxt's `bg-elevated` and `ring-accented` treatments: a lighter surface with an edge that remains visible against it. These resolve through the application's `--ui-bg-elevated` and `--ui-border-accented` tokens. Light mode retains native UToast background/ring defaults, and both modes retain its native shadow. This is an adapter choice, not Nuxt UI's upstream default, and requires no demo stylesheet or business-side styling.

Notifications compose native UCard and UButton with an optional title/close header, a full-width body with normal content typography, and an optional action footer. The Card footer supplies the theme's action spacing. Nuxt UI has no separate native Notification component. The adapter supplies a short fade/slide transition, honors reduced motion, and bounds the card to the viewport. The body is a named keyboard-focusable scroll region; header and footer remain outside its scrolling content. Arrival does not capture focus. Rich content retains its component identity through message updates.

Notification cards use Nuxt's `--ui-bg` in light mode and `--ui-bg-elevated` in dark mode. A 1 px ring uses `--ui-border-accented` in both modes, and the adapter adds a deeper shadow to separate the notification from the page. Applications can set `--uninterface-notification-shadow` through [the Nuxt theme](customization.md#notification-card-elevation).

The native toast root receives a primary-color halo when it is itself `:focus-visible`. For notifications, direct keyboard focus on the scrollable body represents focus on the notification: the halo surrounds the whole card, without a second outline around the body. Focus on an input, link, close/action button or other child control does not activate the outer halo; that control retains its own focus treatment. The notification card has no extra tab stop, and the body remains the actual keyboard scroll target. The halo matches the backend's other focus surfaces: three pixels of `--ui-primary` at 25% opacity, with a two-pixel `Highlight` outline in forced colors. It remains independent of decorative rings/shadows. The managed viewport has an inward outline when used as a fallback focus destination. No extra tab stop or focus capture is added. Verify actual Tab/Shift+Tab traversal, clearance, focus pause/resume and both color modes; DOM matching does not establish painted visibility.

Both surfaces show native UProgress for timed deliveries, driven by the target’s remaining-time clock including overlapping hover/focus/document pauses. Persistent deliveries omit progress. The viewport leaves room for native rings/shadows. App-owned configuration through the backend Vite hook accepts `ui.toast`/`ui.toaster` for toasts, `ui.card`/`ui.button` for notifications, and `ui.progress` for countdowns; see [customization](./customization.md). Adapter CSS owns bounds, scrolling and notification motion. Verify concurrent rich forms, changing-height content, modal scope, narrow/RTL layout, focus and exits before claiming browser/AT acceptance.

## Key-value allocation

UiKeyValueList shares a content-sized label column across its items, capped at half the list width; values receive the remainder. The adapter uses CSS Grid subgrid to retain alignment without requiring consumer widths. A list at or below 18rem stacks each label above its value using a container query, including narrow notifications on wide screens. Long labels and values can wrap, and nested lists establish their own allocation. This is backend presentation, not an author-facing sizing API. Check short values with longer labels, translations, rich values, nested lists and narrow LTR/RTL containers in a browser.
